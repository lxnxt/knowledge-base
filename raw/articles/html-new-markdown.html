HTML 会成为新的 Markdown 吗？

TL;DR：Claude Code 工程师 Thariq 提出"HTML 是新的 Markdown"——用 AI 生成结构化 HTML，比长 Markdown 文档更易于阅读和分享。

文档越来越长，越来越难读

作者的习惯：给 AI 一次口喷 10 分钟数千字，让 AI 完善想法。最终产出的文档可能有 300-1000 行。

作者更倾向于让 AI 一次性完成较大的任务，减少与 AI 沟通的频率，减少自己在其中 loop 的次数。

买菜 vs AI coding 的往返对比

去菜市场买菜，你会一次性买齐所有东西回家，减少路上的时间。

在 AI coding 中，"路上的时间"就是 AI 说"我干完了，你来看看"后，你需要一次又一次对这些小任务进行的多次检查验收。

核心痛点

  • 大文档接手的同事不会一行一行看
  • 要么直接扔给 AI 分析开干
  • 更希望有人在方案环节就进行 review，而不是完成后再发现初始方案的问题
  • AI 产出的文档容易前后矛盾

HTML vs Markdown 的核心差异

同样的内容，不同的交付：

  • Markdown：240 行，底部写着「还有 214 行」，需要滚动阅读
  • HTML：有 tab 切换、有数据图表、有关键指标高亮，扫一眼就能抓住重点

一个是让你滚动阅读的文档，一个是让你扫一眼就能抓住重点的页面。

HTML 的优势

信息密度更高

HTML 能承载的信息类型比 Markdown 丰富太多——图表、指标高亮、交互元素。

更适合阅读

一个让你滚动阅读，一个让你扫一眼就能抓住重点。

分享门槛低

Claude Code 可以直接生成可直接分享的 HTML 页面。

双向互动

HTML 支持交互，Markdown 只能静态呈现。

结论

AI 时代，精炼的语言、更少的 token 来表达同样的内容，是更重要的技能。

HTML 作为载体，比 Markdown 更适合 AI 时代的信息传递——而 Claude Code 让生成 HTML 变得和写 Markdown 一样简单。
